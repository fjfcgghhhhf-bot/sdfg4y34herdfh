# Рулетка дебаффов: сайт + Windows-клиент

Панель на русском управляет **всеми 18 событиями** прежней программы. На ПК игрока остаются колесо, таймер, статус связи и аварийный выход. Клиент подключается добровольно; автозапуска и скрытого режима нет.

## Быстрый запуск

1. Разверните репозиторий на Render по инструкции ниже.
2. Откройте полученный HTTPS-адрес и войдите с `ADMIN_PASSWORD`.
3. Нажмите **«Подключить игрока»**. Получите одноразовый код на 10 минут.
4. На ПК игрока закройте старую рулетку через F12. Запустите `DebuffRemoteClient.exe` и подтвердите обычный запрос администратора Windows.
5. Введите адрес сайта, уникальный ник и код. Подтвердите разрешение управления.
6. Игрок появится в панели. Выберите его или **«Все игроки в сети»**, затем событие либо таймер.

Ник, адрес и настройки сохраняются в `%LOCALAPPDATA%\DotaDebuffRemote\client.json`. Токен защищён Windows DPAPI текущего пользователя. При последующих запусках ник повторно не спрашивается, но разрешение на сеанс подтверждается. После потери связи нажмите «Подключиться»; для другого сайта или нового кода — «Адрес / новый код». Доступен также запуск `DebuffRemoteClient.exe --configure`.

## Что есть на сайте

- Игроки в сети, последние статусы и таймеры; выбор одного, нескольких или всех присутствующих.
- Рулетка с интервалом 120 секунд; вращение сейчас; остановка и снятие эффектов.
- Ручной запуск каждого события независимо от его галочки в случайном наборе.
- Настройка случайного набора, громкости, клавиши ТП, магазина, координат и провайдера ИИ; деморежим.
- Запоминание позиции ТП через 3 секунды. Координаты считываются на ПК игрока.
- Выбор видео и предпросмотр. Кнопка сайта открывает у игрока диалог выбора локального файла; произвольные удалённые пути и загрузка программ не поддерживаются.
- Журнал последних 60 команд. «Принята» означает приём команды; реальный результат показан в карточке игрока.
- Одноразовые коды и отзыв доступа. Отозванный клиент снимает эффекты при следующем запросе/истечении связи.

| Событие | Действие |
|---|---|
| Смена кнопок мыши / инверсия | По 20 секунд |
| ТП на базу | ТП и блок ввода на 6 секунд |
| Смена окна | Другое окно и блок клавиатуры/мыши на 5 секунд |
| Видео | Правая половина экрана, звук, 30 секунд, одно нажатие Win |
| Клавиатура / мышь / оба устройства | По 3 секунды |
| Закрыть Dota 2 | Только процесс с точным именем `dota2.exe` |
| Купить ТП | 1–10 свитков; блок мыши во время покупки, максимум 5 секунд |
| Переворот экрана | 180°, 30 секунд, затем восстановление |
| Консоль | `color 2`, `dir /s` в папке приложения, по центру на 10 секунд |
| Монитор | Выключение на 10 секунд с восстановлением |
| Пинг-понг | Четверть экрана; ↑/↓; выдержать 30 секунд; промах закрывает Dota |
| Второй рабочий стол | Перейти на стол 2, создать при отсутствии |
| Красные кубы | Прыгают 40 секунд; максимум 4, каждый живёт 5 секунд |
| Шахматы | Четверть экрана; 25-й ход игрока сразу даёт победу; мат или <25 ходов за минуту — поражение |
| Убеди ИИ | Четверть экрана; минута, начальный градус 80%, +2 п.п./с, охлаждение до 20 п.п. за ответ; итог >70% закрывает Dota |

При ошибке ИИ событие отменяется без закрытия игры. Процент — игровая шкала. На сервер и провайдеру передаётся только чат мини-игры и текущий градус, без файлов, скриншотов и посторонних нажатий клавиш.

## Архитектура и структура

```text
Браузер администратора → HTTPS / Flask → SQLite
                                         ↑
                            REST polling раз в секунду
                                         ↓
                              PyQt6-клиент → события
                                         ↓
                      серверный шлюз ИИ → Gemini / Groq
```

```text
server.py                 # Flask: авторизация, игроки, команды, SQLite
wsgi.py                   # точка входа Gunicorn
protocol.py               # общий список событий и проверка команд
ai_gateway.py, ai_rules.py # серверные обращения к ИИ
templates/                # вход и панель
static/                   # CSS и JavaScript без внешних CDN
client.py                 # первый запуск, ник, разрешение, главное окно
desktop/remote_*.py       # клиент REST, оболочка, ИИ через сервер
desktop/client_store.py   # локальные настройки и DPAPI
desktop/*.py              # прежние обработчики 18 событий
desktop/assets/           # встроенное видео и русские переводы Qt
tests/                    # серверные проверки и HTTP + Qt интеграция
requirements.txt          # зависимости сайта
client-requirements.txt   # зависимости клиента
build_client.ps1          # сборка EXE
render.yaml, Procfile     # конфигурация Render
```

Используется один процесс Gunicorn с 8 потоками. SQLite работает в WAL-режиме. Администратор защищён паролем, сессией HttpOnly/SameSite, CSRF и проверкой источника. На сервере хранятся хеши клиентских токенов и кодов.

Команды живут **8 секунд**, адресуются конкретному сеансу и доставляются **не более одного раза**. Новая команда заменяет ожидающую. После потери ответа действие не отправляется повторно: это предотвращает повторную покупку или закрытие игры. Статус «Доставлена» без подтверждения означает неопределённый результат доставки; проверьте карточку перед повторной отправкой.

При отсутствии связи до 8 секунд клиент ставит таймер на паузу и снимает эффекты. Перезапуск сервера аннулирует старые сеансы и очереди. Повторное подключение не возобновляет таймер самостоятельно. Выбор «Все» означает игроков онлайн в момент команды, а не будущие подключения.

## Render — пошагово

1. Войдите в [Render Dashboard](https://dashboard.render.com/).
2. **New → Blueprint**, подключите указанный GitHub-репозиторий и ветку `main`.
3. Render прочитает `render.yaml`. Проверьте план **Free** либо выберите подходящий план самостоятельно.
4. Задайте `ADMIN_PASSWORD` — длинный личный пароль от 16 символов. `SECRET_KEY` Blueprint генерирует автоматически.
5. В Environment укажите `GEMINI_API_KEY` для Gemini или `GROQ_API_KEY` для Groq. В этой версии ключи задаются на сервере, а не в EXE. Реальные ключи из переписки в репозиторий не включены. Если провайдер не нужен, оставьте его ключ пустым; нужного провайдера выберите в настройках панели.
6. Модели задаются переменными `GEMINI_MODEL` (по умолчанию `gemini-2.5-flash`) и `GROQ_MODEL` (`openai/gpt-oss-20b`). Доступность зависит от аккаунта провайдера; при ошибке мини-игра отменяется.
7. Нажмите **Deploy Blueprint**. Дождитесь статуса Live, откройте HTTPS-адрес `https://имя.onrender.com` и войдите.
8. Этот же адрес вводится в клиенте. Пересобирать EXE при смене сайта не требуется.

Альтернатива **New → Web Service**:

| Поле | Значение |
|---|---|
| Runtime | Python 3 |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `gunicorn --workers 1 --threads 8 --timeout 40 --bind 0.0.0.0:$PORT wsgi:app` |
| Health Check | `/healthz` |
| Environment | `SECRET_KEY` (32+ случайных символа), `ADMIN_PASSWORD`, `COOKIE_SECURE=1`, ключ ИИ |

**Хранение SQLite:** файловая система Render без диска временная. После рестарта/деплоя база может исчезнуть: понадобится выдать новые коды и переподключить клиентов. Для постоянного хранения используйте платный сервис с диском, например mount path `/var/data`, и `DATABASE_PATH=/var/data/roulette.sqlite3`. Диск подключается пользователем в Render; проект сам не оформляет платные услуги. Инстанс должен оставаться один.

Документация: [Flask на Render](https://render.com/docs/deploy-flask), [постоянные диски](https://render.com/docs/disks). На бесплатном сервисе возможен холодный старт: дождитесь открытия сайта, затем подключайте клиента.

## Локальная проверка сервера

Python 3.11+:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:SECRET_KEY = 'укажите-случайную-строку-не-короче-32-символов'
$env:ADMIN_PASSWORD = 'укажите-свой-пароль-от-16-символов'
$env:COOKIE_SECURE = '0'
.\.venv\Scripts\python.exe -m flask --app 'server:create_app' run --host 127.0.0.1 --port 8765
```

Откройте `http://127.0.0.1:8765`. HTTP разрешён клиентом только для localhost. Для Render всегда используйте HTTPS и `COOKIE_SECURE=1`. `.env.example` — образец; приложение автоматически его не читает.

## Сборка Windows EXE

На Windows x64 установите Python 3.11+ с launcher `py`, затем из папки проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_client.ps1
```

Результат: `dist\DebuffRemoteClient.exe`, Python у игрока не требуется. Встроены видео и переводы. Точный ручной вариант:

```powershell
py -3 -m venv .build-venv
.\.build-venv\Scripts\python.exe -m pip install -r client-requirements.txt pyinstaller
$env:PATH = "$PWD\.build-venv\Scripts;$PWD\.build-venv\Lib\site-packages\PyQt6\Qt6\bin;$env:SystemRoot\System32;$env:SystemRoot"
.\.build-venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --onefile --windowed --uac-admin --name DebuffRemoteClient --paths desktop --add-data "desktop/assets;assets" --add-data "LICENSE-chess.txt;." client.py
```

`--onefile` — один EXE; `--windowed` — без служебной консоли; `--uac-admin` — обычный запрос UAC. Права администратора нужны для некоторых действий ввода/окон; UAC не обходится. Зависимости клиента: PyQt6, psutil, pyvda, chess. Для API используется QtNetwork.

Адрес задаётся в первом диалоге; переменная `ROULETTE_SERVER_URL` может предзаполнить его. Для проверки без системных действий запустите `DebuffRemoteClient.exe --demo`: сайт не может отключить этот локальный режим.

## Проверки и ограничения

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
# Отдельно на Windows, после установки client-requirements.txt в это окружение:
.\.venv\Scripts\python.exe tests\integration_client.py
```

Проверены авторизация/CSRF, уникальность ников, одноразовые коды, 18 команд и адресация, массовая отправка, отзыв доступа, истечение команд, отсутствие повторов, перезапуск SQLite, форматы обоих провайдеров ИИ. Сквозная проверка HTTP + Qt использует принудительное демо и заменяет системный контроллер: все 18 событий, таймер, настройки и обрыв связи. DPAPI проверен записью и чтением тестового токена. Панель просмотрена в браузере на фиктивных игроках.

Живой матч, выключение монитора и блокировка ввода в этой итерации не запускались. Унаследованные ограничения остаются: Raw Input игры может обходить эмуляцию мыши, Windows может запрещать активацию окна. Для оверлеев используйте оконный режим Dota без рамки. Вызовы реальных Gemini/Groq с серверными ключами после деплоя нужно проверить отдельно.

**F12** закрывает клиент и снимает эффекты; **Esc** отменяет мини-игру. Обработчик F12 независим от сети; восстановление монитора и поворота защищено отдельными помощниками. Из удалённых команд невозможно передать произвольный Python, shell-команду, имя процесса или путь файла. Сайт не получает доступ к экрану или документам игрока.

`chess` распространяется по GPL-3.0-or-later, лицензия находится в `LICENSE-chess.txt`. Исходники клиентской сборки поставляются вместе с проектом.
