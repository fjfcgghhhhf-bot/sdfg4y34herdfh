# Рулетка дебаффов · версия 3.1

Русская веб-панель и Windows-клиент с **21 событием**. Игрок подключается добровольно; клиент показывает колесо, таймер, состояние и аварийный выход. Автозапуска и скрытого режима нет.

Панель: [dota-debuff-panel.onrender.com](https://dota-debuff-panel.onrender.com/).
Репозиторий: [fjfcgghhhhf-bot/sdfg4y34herdfh](https://github.com/fjfcgghhhhf-bot/sdfg4y34herdfh).

## Запуск и обновление

1. Войдите на сайт с паролем `ADMIN_PASSWORD`. Создайте одноразовый код кнопкой «Подключить игрока».
2. Закройте прежнюю рулетку через **F12** на каждом ПК. Запустите **DebuffRemoteClientV3_1.exe**, подтвердите запрос администратора Windows.
3. При первом запуске введите адрес сайта, ник и код. Разрешите события для этого сеанса.
4. Выберите игрока или «Все игроки в сети» на сайте. Запустите событие или авторулетку с интервалом 120 секунд.

Ник, адрес и настройки хранятся в `%LOCALAPPDATA%\DotaDebuffRemote\client.json`. Токен защищён Windows DPAPI. При последующих запусках запрашивается только разрешение на сеанс. Старый клиент необходимо заменить на V3; новый сервер разрешает ему только остановку. Сохранённые ник и токен используются новой версией автоматически. После деплоя обновите страницу панели и переподключите клиенты.

Новый код нужен при отзыве доступа или потере базы Render. Для его ввода используйте «Адрес / новый код» либо `DebuffRemoteClientV3_1.exe --configure`. После обрыва связи нажмите «Подключиться»; таймер сам не возобновляется.

## Управление на сайте

- Выберите одного, нескольких или всех игроков онлайн в момент команды.
- **Длительность в карточке** применяется к следующему ручному запуску события.
- В карточке апгрейдера **шанс 0–100%** управляет размером нижнего оранжевого сектора. Значение сохраняется для авторулетки вместе с настройками игрока.
- У музыки отдельный слайдер **0–100%**. Можно менять громкость уже запущенного трека без его остановки; громкость видео не меняется. При обновлении старая общая громкость становится начальной громкостью музыки.
- Для индивидуальной настройки авторулетки выберите игрока, нажмите **«Загрузить настройки игрока»**, измените секунды и случайный набор, затем **«Применить настройки»**. Для группы сохранится общий выбранный набор.
- Регулируются громкость видео/музыки, провайдер ИИ, клавиша магазина и координаты иконки ТП. ТП на базу всегда отправляет **T дважды**.
- «Запомнить позицию ТП» считывает координаты курсора через 3 секунды на ПК игрока.
- «Выбрать видео» и «Добавить музыку» открывают у игрока локальный диалог. Сервер не задаёт произвольные пути.
- Кнопка копирования копирует **только одноразовый код**, без пояснений и адреса.
- Карточки показывают связь, событие, таймер, матч и оставшийся иммунитет. «Принята» в журнале означает получение команды; результат смотрите в карточке.

### Шахматы и пинг-понг 1 на 1

Выберите двоих свободных игроков или чётное число — сервер распределит их по парам. При выпадении в авторулетке подбирается свободный игрок в сети с включённым событием. Без соперника событие пропускается. Демо-клиент отменяет матч.

Сервер проверяет шахматные ходы и рассчитывает мяч. Поддержаны рокировка, взятие на проходе и выбор превращения. Ничья автоматически фиксируется и при достижении условий её заявления (троекратное повторение, 50 ходов).

**Dota закрывается только у проигравшего.** Ничья, Esc, «Стоп», ошибка или обнаруженный обрыв связи отменяют матч без штрафа. В пинг-понге первый пропущенный мяч — поражение. Окно должно иметь фокус для стрелок; есть также кнопки ↑/↓. Пауза обновления физики больше секунды отменяет матч. Авторулетка не прерывает матч, ручное другое событие отменяет его. После разрыва сеанса прежний результат не воспроизводится заново.

### Апгрейдер и иммунитет

Обычный шанс победы настраивается от **0 до 100%** (по умолчанию 50%). Нижний оранжевый сектор занимает соответствующую часть окружности и расширяется симметрично вокруг нижней точки. В центре показаны процент и описание шанса; стрелка вращается по внешнему краю. В центре — золотая буква «R». После остановки стрелки круг плавно заполняется зелёным при победе или иммунитете и красным при проигрыше (0,6 секунды). Полная заливка остаётся на экране ещё 2 секунды, затем применяется результат и окно закрывается. Выбранная на сайте длительность задаёт время вращения; показ результата добавляет 2,6 секунды. Esc и F12 доступны на всех этапах.

Сервер делает два отдельных броска: появление золотого «?» с вероятностью **30%**, затем попадание в него с вероятностью **30% при условии появления**. Общая вероятность иммунитета — **9% за вращение**. При отсутствии бонусного попадания обычная победа разыгрывается с настроенным шансом. Например, при 50% обычного шанса: 45,5% побед, 45,5% поражений и 9% иммунитета.

Золотая цель остаётся небольшой и располагается в центре нижнего сектора. Её ширина — до 16°, при малом обычном шансе она сужается. Это отдельный бонус со своей вероятностью: размер золотой цели не определяет шанс попадания. Сервер сначала выбирает результат, затем конечный угол строго внутри соответствующей зоны. При 0% обычной победы бонус также может выпасть; при 100% обычное поражение невозможно.

Иммунитет длится 10 минут после анимации, виден на сайте и клиенте, блокирует все ручные/случайные события и подбор в матч. Сервер хранит его в SQLite, клиент дублирует проверку локально. По истечении таймер запускается снова вручную. F12, остановка и настройки доступны всегда.

### Музыка и ИИ

В `desktop/assets/music/` включены MP3 из [предоставленного YouTube-видео](https://youtu.be/aZWWlqDy8nE), аудиодорожка предоставленного Subway Surfers MP4 и **«Пенис (BEARWOLF cover)»** из приложенного файла. `catalog.json` задаёт названия. Свои MP3/WAV/OGG/FLAC/M4A добавляются локальным диалогом и видны при выборе одного игрока на сайте. Для группы доступны все три встроенные дорожки. Системная громкость не меняется.

ИИ работает через серверный шлюз Gemini/Groq. Процент — игровая шкала, а не измерение скрытого внутреннего состояния модели. При ошибке провайдера событие отменяется без закрытия Dota. На сервер и провайдеру передаются только сообщения мини-игры и текущий градус. Ключей API в EXE и репозитории нет.

## Структура проекта

```text
server.py, wsgi.py          Flask, авторизация, команды, SQLite
matches.py                 серверные шахматы и физика пинг-понга
protocol.py                список событий, версия и проверка команд
upgrade_rules.py           независимые вероятности апгрейдера и конечный угол
ai_gateway.py, ai_rules.py  запросы к Gemini/Groq
templates/, static/        русский интерфейс, CSS и JavaScript
client.py                  первый запуск, ник и разрешение
desktop/remote_*.py        связь, оболочка и серверный ИИ
desktop/multiplayer.py     сетевые мини-игры
desktop/upgrader.py        анимация стрелки
desktop/music_event.py     музыка и локальный каталог
desktop/grayscale.py       фильтр с независимым восстановлением
desktop/client_store.py    сохранение настроек и DPAPI
desktop/*.py               прежние обработчики ввода, экрана и оверлеев
desktop/assets/            видео, музыка, русские переводы Qt
tests/                     серверные тесты и сквозные HTTP + Qt проверки
requirements.txt           зависимости сервера
client-requirements.txt    зависимости клиента
build_client.ps1           сборка Windows EXE
render.yaml, Procfile      запуск на Render
```

Один процесс Gunicorn, 8 потоков; **не увеличивайте workers/число инстансов**: активные матчи хранятся в памяти. Перезапуск отменяет матчи без штрафа. SQLite работает в WAL-режиме. Команды ограничены фиксированным списком, живут 8 секунд, адресованы сеансу и доставляются не более одного раза. Потерянная доставка не повторяет покупку/закрытие игры. Новая команда заменяет ожидающую.

Админ-панель использует пароль, сессию HttpOnly/SameSite, CSRF и проверку источника. Токены и одноразовые коды хранятся в виде хешей. Потеря связи до 8 секунд снимает эффекты и ставит таймер на паузу. Авторизация не даёт возможности отправлять произвольный Python, shell-команду, имя процесса или путь файла.

## Render

1. **New → Blueprint**, выберите репозиторий и `main`; Render прочитает `render.yaml`. Либо создайте Python Web Service вручную.
2. Build Command: `pip install -r requirements.txt`.
3. Start Command: `gunicorn --workers 1 --threads 8 --timeout 40 --bind 0.0.0.0:$PORT wsgi:app`.
4. Health Check: `/healthz`.
5. Environment: `SECRET_KEY` (32+ случайных символа), `ADMIN_PASSWORD` (16+ символов), `COOKIE_SECURE=1`. Blueprint генерирует `SECRET_KEY`.
6. Для ИИ задайте `GEMINI_API_KEY` или `GROQ_API_KEY`. Модели: `GEMINI_MODEL=gemini-2.5-flash`, `GROQ_MODEL=openai/gpt-oss-20b`. При недоступности модели мини-игра отменяется.
7. Дождитесь Live, откройте сайт, войдите. Тот же HTTPS-адрес вводится в клиенте. Пересборка при смене адреса не нужна.

Существующий сервис с автодеплоем обновляется после push в `main`. На бесплатном Render файловая система временная: после деплоя база может исчезнуть, тогда выдайте игрокам новые коды. Для постоянной SQLite нужен диск, например `/var/data`, и `DATABASE_PATH=/var/data/roulette.sqlite3`. Платный диск подключается пользователем; проект не оформляет платные услуги. Холодный старт: дождитесь открытия сайта перед подключением клиентов.

Документация: [Flask на Render](https://render.com/docs/deploy-flask), [диски](https://render.com/docs/disks).

## Локальный сервер

Python 3.11+:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
$env:SECRET_KEY = 'случайная-строка-не-короче-32-символов'
$env:ADMIN_PASSWORD = 'личный-пароль-от-16-символов'
$env:COOKIE_SECURE = '0'
.\.venv\Scripts\python.exe -m flask --app 'server:create_app' run --host 127.0.0.1 --port 8765
```

Откройте `http://127.0.0.1:8765`. HTTP разрешён клиентом только на localhost. `.env.example` — образец, не считывается автоматически.

## Сборка EXE на Windows x64

Установите Python 3.11+ с launcher `py`. Из папки проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\build_client.ps1
```

Результат — **dist\DebuffRemoteClientV3_1.exe**, со встроенными видео, музыкой и переводами. Python на ПК игрока не требуется. Точная ручная команда:

```powershell
py -3 -m venv .build-venv
.\.build-venv\Scripts\python.exe -m pip install -r client-requirements.txt pyinstaller
$env:PATH = "$PWD\.build-venv\Scripts;$PWD\.build-venv\Lib\site-packages\PyQt6\Qt6\bin;$env:SystemRoot\System32;$env:SystemRoot"
.\.build-venv\Scripts\python.exe -m PyInstaller --noconfirm --clean --onefile --windowed --uac-admin --name DebuffRemoteClientV3_1 --paths desktop --add-data "desktop/assets;assets" --add-data "LICENSE-chess.txt;." client.py
```

`--onefile` создаёт один EXE, `--windowed` убирает служебную консоль, `--uac-admin` запрашивает обычное повышение через UAC. Зависимости клиента: PyQt6, psutil, pyvda, chess; HTTP использует QtNetwork. Сервер: Flask, requests, chess, Gunicorn на Linux. [Документация PyInstaller](https://pyinstaller.org/en/stable/usage.html).

Адрес задаётся в первом диалоге; `ROULETTE_SERVER_URL` предзаполняет его. `DebuffRemoteClientV3_1.exe --demo` принудительно запрещает системные действия; сайт не может отключить этот режим.

## Проверки и ограничения

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_*.py" -v
# Следующие проверки — Windows с установленными client-requirements.txt:
.\.venv\Scripts\python.exe tests\integration_client.py
.\.venv\Scripts\python.exe tests\integration_v2.py
.\.venv\Scripts\python.exe tests\check_grayscale.py
```

Проверяются CSRF и вход с Origin:null, уникальность ников, коды, адресация, сроки и отсутствие повтора команд, отзыв доступа, перезапуск, форматы ИИ, длительности, легальность ходов/мат/ничья, первый промах, отмена, независимые броски апгрейдера и иммунитет. Сквозные проверки запускают реальные HTTP/Qt-клиенты с заменой системных действий: 19 одиночных событий в демо, матч двух клиентов, наказание только проигравшему, отмена без наказания. Восстановление цветовой матрицы проверяется с подменой Windows API; отдельно проверена доступность API без изменения цветов.

В реальном матче Dota новые эффекты не проверялись. Raw Input игры может обходить эмуляцию мыши; Windows может отклонять активацию окна. Оверлеи требуют оконного режима Dota без рамки. Цветовой фильтр зависит от поддержки Windows/драйвера. Запросы к реальным Gemini/Groq после деплоя требуют действующих ключей на сервере.

**F12** снимает эффекты и закрывает клиент, **Esc** отменяет мини-игру. Восстановление монитора, поворота и цветов выполняется независимыми помощниками даже при завершении GUI. Консоль закрывается по таймеру или F12, несмотря на отключённый крестик. Изменения реестра, чужих файлов и произвольные удалённые команды не используются.

`chess` распространяется по GPL-3.0-or-later, см. `LICENSE-chess.txt`. Исходники клиента поставляются вместе с проектом.
